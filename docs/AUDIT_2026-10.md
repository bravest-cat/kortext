# kortext audit, October 2026

Audit of bravest-cat/kortext against the brief in `message.txt`, done 2026-10-25 to 2026-10-28.

## How it was done

- **Code reading.** Ten read-only passes by Antigravity (Gemini 3.8 Flash, High effort), one per area: core, security and dashboard, retrieval, episodic and learning, task DAG, chunking and symbols, tests and benchmarks, agy docs and HUD, web sources, ECC and memory research. Every finding had to quote the offending line.
- **Verification.** Each critical and high finding was checked against the code by hand before it went into this report. Gemini output that did not survive the check is listed in section 2.4. Medium and low findings were not all re-checked; the raw reports are kept and can be sent on request.
- **Measurement.** Every number here was measured on the code, not taken from docs or old reports. The suite was run against real FalkorDB and Qdrant (CI's pinned images, local containers), not the regex emulator.
- **Validator.** `agy plugin validate` (agy 1.4.8) was run on the plugin.

The fixes are in four PRs. #1 is merged. #2, #3 and #4 are open and stacked, so merge them in order.

| PR | Branch | What |
|---|---|---|
| #1 | merged 2026-10-26 | Setup wizard test isolation |
| #2 | `fix/honest-benchmarks` | 8 s hook stall, LongMemEval through production search, real-DB tests, CI green on 3 OSes |
| #3 | `fix/runtime-hardening` | Runtime files out of the repo, silent-failure logging, stub cleanup, portable hooks, systemd units |
| #4 | `fix/audit-followups` | The fixes in section 2.1 |

Result on the #4 branch: **698 passed, 1 xfailed** against real FalkorDB and Qdrant.

## 1. Verdict matrix

Value means measurable gain in tokens, latency or correctness. Bloat means complexity and moving parts for what it delivers. Grades come from the code reading. Where a grade rests on a bug, the bug is listed in section 2.

| Subsystem | Value | Bloat | Verdict |
|---|---|---|---|
| Symbol graph, `seek_symbol`, `trace_symbol_impact` | High | High | Main reason to use kortext. Homonym fan-out and Cartesian queries need work (2.2) |
| Hybrid dense + sparse search | High | Medium | Reliable base of retrieval |
| Lifecycle hooks | High | High | Grep and view gating saves tokens. 800-line `pre_tool.py` is heuristic-heavy. Was stalling 8 s per call (fixed in #2) |
| AST chunking and ingest | High | Medium | Works. Config files over 2048 characters are cut silently (2.2) |
| FalkorDB client | High | Medium | Fine after the #2 timeout fix |
| Episodic memory | Low today | Medium | Bi-temporal design is sound. Search is a token-overlap match: F1 0.07 to 0.28, never abstains |
| Task DAG | Medium | Medium | Atomic claim works. Review gate was bypassable (fixed). Overlap detection gives false positives |
| Invariant grounding | High | High | Sound design. Signature-anchored drift check is intentional |
| Dream mode | Medium | High | Pruning deleted facts before archiving them (fixed). Not project-scoped |
| Federated 4-tier retrieval | Medium | High | Token budgeting is useful; Windows path bug fixed |
| HippoRAG PPR | Low | High | Column normalisation cancels most of the hub discount, and dangling nodes leak mass. No measured gain over dense + sparse |
| TAA-k knee trimmer | None | Medium | Inert: called with `k_min >= top_k`, then sliced to `top_k`, so it never drops anything |
| Weibull retention decay | Low | Medium | Down-weights old but stable code chunks |
| Reranker | Low | Medium | 250 ms timeout per query when no server; offline fallback outweighs the fusion score |
| Trust and sanitizer | Medium | Medium | Regex filter. Promotion fence was open (fixed); provenance fence is never called |
| Instinct store | Low | High | Unlocked JSON read-modify-write; transcript facts were labelled tool-confirmed (fixed) |
| Dashboard | Low | High | Loopback-only with origin checks. Path traversal fixed. No auth if bound elsewhere |
| Subagents (5) | None before #4 | | agy skipped all 5 on load. Fixed |
| Skills (12), rules (8), sidecars (2) | Medium | Low | Pass `agy plugin validate` |
| Statusline | Medium | Medium | Fast when cached; cold path imports the tracker and hits FalkorDB synchronously |

Recommendation: keep symbols, hybrid search, hooks and the task DAG. Fix or cut HippoRAG, TAA-k and the offline reranker; today they cost latency and code with no measured gain. Episodic memory needs its search rewritten before it is advertised.

|---|---|---|---|

## 3. Tests and benchmarks

What the suite measured before #2:
- Unless port 6379 answers, `tests/conftest.py` swaps FalkorDB for `_sandbox_falkordb_fixture_query`, about 1000 lines of regex matching on Cypher strings. On a laptop without FalkorDB, "all green" said nothing about the graph.
- LongMemEval used a test-only answer method with synonym and stop-word tables tuned to the fixture.
- Tests installed the plugin into the real `~/.gemini/config` and wrote to the real `~/.kortext`.
- Upstream CI had failed on every commit.

LongMemEval, production search path (#2):

| Metric | Reported | Real |
|---|---|---|
| Extraction F1 | 0.86 | 0.28 |
| Knowledge updates F1 | 0.90 | 0.14 |
| Temporal F1 | 0.80 | 0.26 |
| Multi-session F1 | 0.47 | 0.07 |
| Abstention | 0.88 | 0 |

The other benchmarks, measured on real FalkorDB (2026-10-28):

| Benchmark | Real result | Honest? |
|---|---|---|
| HotpotQA "multi-hop" (50 q) | Recall@5 0.420, MRR 0.490 | No. Not HotpotQA: kortext-specific questions that name the answer symbols ("Which class uses `apply_taak_trimming`…"), run against a hand-written graph (`_SEED_SYMBOLS_DATA` in conftest) that contains exactly those symbols. Uses a test-only helper, not an MCP tool |
| Golden Set (20 q) | Recall@5 0.775, MRR 0.900 | No, same setup |
| Memory retention MR-1 to MR-6 | passes | Partly. Real driver calls on synthetic facts; the grep baseline concatenates whole files, which overstates savings |
| Token reduction TR-1 to TR-4 | passes | No. Candidate lists and score drops are built in the test; tokens estimated as characters / 3.4 or / 4 |

The benchmark helper also counted a query's own candidate words as "retrieved" when seek found nothing. Removed in #4; the numbers above did not change, because the seeded graph always matched.

What an honest evaluation needs:
1. Index a real repository (kortext itself is fine) with the production ingest, not a hand-seeded graph.
2. Questions that describe behaviour without naming the symbol.
3. Run only public MCP tools (`search_knowledge_and_memory`, `seek_symbol`, `trace_symbol_impact`).
4. Real database only: refuse to write `data/benchmark_results.json` when the emulator is active.
5. A fair grep baseline (`rg -n -C 5`, not whole files) and a real tokenizer.
6. Keep the LongMemEval abstention bar at 0.80 as a strict xfail until search is fixed (already done).

### 5.2 Hook schema conformance (agy `hooks.md` vs kortext)

Conforms: event names, matchers, timeouts, all response shapes, `transcriptPath`, `modelName`. Gaps (only the first was re-checked by hand):
- PostToolUse `error` at the payload root: fixed (2.1 #15).
- `invocationNum` and `executionNum` are conflated, so on Stop hooks `turn_index` is 1 instead of the invocation number.
- `artifactDirectoryPath` and `stepIdx` are not parsed.
- `"enabled": true` is not written explicitly; the `/hooks` TUI shows toggles only when it is present.
- `permissionOverrides` and the `force_ask` / `deny_unless_prior_grant` decisions are never emitted, so trusted commands still prompt.

### 5.3 `/teamwork` and `/boost` on the task DAG

agy's `/teamwork` has a Sentinel, a Project Orchestrator, Explorers, Workers, Critic, Challenger, Auditor and Success Auditor, with integrity modes (development, demo, benchmark) and exclusive file ownership. `/boost` is an Orchestrator, DeepInvestigator/DeepCoder, synthesis loop. kortext already has most of the parts:

| Role | kortext piece |
|---|---|
| Orchestrator decomposition | `manage_tasks(create_tasks_batch)` with `depends_on` |
| Exclusive file ownership | `detect_file_overlaps` (fix 2.2 overlap bugs first) |
| Explorers / DeepInvestigator | `seek_symbol`, `trace_symbol_impact(upstream)`, `kortext-researcher` |
| Workers / DeepCoder | `claim_task` leases, `kortext-task-runner` |
| Critic | `build_review_diff_bundle`, `validate_reviewer_verdict` (bypass fixed) |
| Challenger | `trace_symbol_impact(downstream)` to find callers to attack |
| Auditor (integrity modes) | `GroundTruthTestGate` (bind proofs to commands first, 2.2) |
| Boost phase 1 | `boost_prompt_context` |
| Synthesis | handoff batons via `memory_session_handoff` |

Missing:
- A `claim_exclusive_files` tool that locks paths per task.
- A PreToolUse rule that denies edits to a file locked by another task, and denies new mocks in `benchmark` mode.

### 5.4 Garcia's multi-agent framework

| Failure mode | kortext today |
|---|---|
| Coordination drift | Task fields carry objective and target files; no required output schema |
| Hallucinated ownership | Completion batons and the review gate (bypass fixed) |
| Silent intermediate failure | Partly fixed (#3 logging, #4 PostToolUse errors) |
| Context bloat | Knapsack token budget in `search_knowledge_and_memory`; seek instead of file reads |
| Schema mismatch | Batons are Pydantic; worker output is free text |
| Tool misuse | `pre_tool` guards; subagent tool lists. agy warns that an unknown tool name in an agent's `tools:` can hang the subagent, and whether `seek_symbol` resolves under that name was not tested |
| Cost explosion | Nothing; no per-task token budget enforcement beyond the tracker field |
| Evaluation difficulty | Ground-truth test gate; benchmarks not yet honest (section 3) |

Of the four patterns, central orchestrator and sequential handoffs are built (DAG plus batons). Parallel specialists need the file-ownership tool. Event-driven handoffs exist only through hooks.

| Pattern or failure mode | kortext | Adaptation |

### 5.6 Skills ecosystems (Superpowers, Pocock, Anthropic, Cursor)

kortext already ships `to-spec`, `to-tickets`, `subagent-driven-development`, `systematic-debugging`, `tdd-workflow`, `verification-before-completion`, `code-review` and `security-review`. Worth adding:
- A glossary (Pocock `GLOSSARY.md`) indexed into memory, so names in the graph and in prose agree.
- `/retro`, which reviews retrieval misses after a session and suggests index changes.
- A clear split between user-invoked skills (reindex, dream, flush) and model-invoked ones.
- Progressive disclosure: keep each `SKILL.md` short and move tables into bundled files. The 12 skills total 56 KB.

### 5.7 Statusline and agy-hud

agy-hud renders from the cached `hud_state.json` in under 2 ms and refreshes in a detached child. kortext's statusline does the same while the cache is fresh, but on a cold or stale cache it imports the tracker and queries FalkorDB in the render path. Port the detached refresh, partition token figures by session, and add a plain-text fallback for terminals without Nerd Fonts.
